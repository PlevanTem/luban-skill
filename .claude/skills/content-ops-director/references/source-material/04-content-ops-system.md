## 核心机制事实

### Core-Asset Fanout 模型
- **1 个核心资产 → 5+ channel fanout** 是高 ROI 默认范式
- Repurposing 自动填 **70-80%** 的 calendar slot
- 典型 fanout：monthly webinar → blog post + LinkedIn carousel + email newsletter + YouTube Shorts + podcast clip
- 不是为每个 channel 独立生产（错配方向）

### Content Ops Framework 关键层
- **Strategy** layer — documented strategy + ICP + content pillar
- **Planning** layer — editorial calendar + asset prioritization
- **Production** layer — workflow / approval / quality gate
- **Distribution** layer — channel adaptation + fanout
- **Measurement** layer — channel ROI + attribution
- **Optimization** layer — feedback loop + iteration

### Editorial Calendar 的关键判断
- 不是 "每周发 N 篇" — 是 "每 N 周一个 core asset，然后 fanout"
- Calendar 应当映射到 buyer journey 各阶段（top / middle / bottom of funnel）
- 季度主题（quarterly theme）是结构化的高阶 unit

## 对 capability map 的直接信号

- "Content Ops 系统" 分支必须有：
  - 6-layer framework（Strategy / Planning / Production / Distribution / Measurement / Optimization）
  - Core-asset fanout 范式（不是 channel-first 生产）
  - Repurposing 填 70-80% 的事实
- "Editorial calendar 设计" 分支必须有：
  - 按 buyer journey / funnel 阶段映射
  - 季度 theme + 月度 core asset 的层级结构
- "团队 / 头数" 分支：3-5 人小团队是 B2B SaaS content ops 的常见配置（reference: 小橘 3 人例 + averi 普遍 benchmark）

## 对 anchors 的直接信号

- **Sacred constraint 候选**：channel-first 生产是反系统的，必须 core-asset-first
- **Stance 候选**：editorial calendar 不是 frequency table，是 buyer-journey × core-asset 的矩阵
- **Sacred constraint 候选**：没有 attribution / measurement layer 的 content ops = vanity ops，无论产能多高
