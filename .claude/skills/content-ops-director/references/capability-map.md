## 1. Strategy & Documentation

### 1.1 Documented strategy 与 ICP
- 可以判断一个 content team 是否有 documented strategy（不是"我们有 doc"，而是 ICP + content pillar + 季度 theme 三件套是否对齐）[来源：src-01-benchmarks]
- 知道 documented strategy 是 3x leverage 的事实数据 [来源：src-01-benchmarks]
- 可以从 ICP 反推 content pillar（3-5 个支柱）+ 排除非 ICP-aligned 的 content 提案 [unverified]

### 1.2 Channel ROI 优先级判断
- 可以根据 B2B SaaS benchmark 给 channel mix 顺序（LinkedIn > email > 演讲 > 短视频 > 静态 social）[来源：src-01-benchmarks]
- 可以识别"在低 ROI channel 投入过多产能" 的常见错配 [来源：src-01-benchmarks]

### 1.3 季度 theme + 月度 core asset
- 可以为 12 个月排出季度 theme + 月度 core asset 的 calendar 结构 [来源：src-04-content-ops-system]
- 不允许 "每周 N 篇" 的 frequency-based calendar [来源：src-04-content-ops-system]

## 2. Content Ops System (6-layer framework)

### 2.1 6 层 framework 定位
- 知道 Strategy / Planning / Production / Distribution / Measurement / Optimization 6 层各自职责 [来源：src-04-content-ops-system]
- 可以在被问"我们 content 不 scale" 时定位到具体层（多半是 Production 或 Distribution）[来源：src-04-content-ops-system]

### 2.2 Production workflow / 质量 gate
- 可以为 production 设计 brief → draft → edit → approval → publish 的 SOP [unverified]
- 可以为质量 gate 定义 reject 标准（off-pillar / off-ICP / 无 distribution plan）[unverified]

### 2.3 Distribution layer 跨 channel 适配

- 可以为同一 core asset 给 channel-specific 改写 brief（LinkedIn carousel / Twitter thread / 小红书 AB 版 / 视频号 vertical）[来源：src-02 + src-03]

### 2.4 Measurement & ROI attribution
- 知道 measurement 是 30% B2B team 最大 challenge 的事实 [来源：src-01-benchmarks]

- 拒绝 vanity metrics（impressions / likes）作为决策依据 [来源：src-01 + src-04]

## 3. 海外平台机制

### 3.1 LinkedIn (B2B SaaS 海外主战场)
- 知道 employee/founder personal content 比 company page **8x engagement** [来源：src-02-linkedin]
- 知道 format hierarchy：carousel **278%** > video > 静态 post [来源：src-02-linkedin]
- 知道算法 reward expertise + engagement quality, not frequency [来源：src-02-linkedin]
- 可以设计 founder-led + employee advocacy program 的运营机制 [来源：src-02-linkedin]
- 可以判断 thought leadership ads vs company page ads 的 ROI 差异 [来源：src-02-linkedin]

### 3.2 TikTok / YouTube Shorts / Instagram Reels (短视频)
- 知道 short-form video 60% adoption + 49% 最高 ROI 报告率（但 B2B 转化逻辑不同 B2C）[来源：src-01-benchmarks]
- 知道 B2B short-form 的内容形态：framework explainer / behind-the-scenes / day-in-the-life / customer story [unverified]

### 3.3 Twitter/X / Reddit / Substack / Discord
- 知道 B2B SaaS thought leadership 在 Twitter/X 通过 thread + builder-in-public 形态 [unverified]
- 知道 Reddit 是 B2B 软性 community 投放渠道，但反 promotional [unverified]
- 知道 Substack newsletter 是 B2B 私域承接的海外标准 [来源：src-01-benchmarks 中 email ROI $42:$1 延伸]

## 4. 国内平台机制

### 4.1 小红书 B2B
- 知道 **85% B2B 企业用双账号策略**（官方 + 创作者半官方身份）[来源：src-03-china-platforms]
- 知道创作者账号粉丝黏性 **3x** 纯官方账号 [来源：src-03-china-platforms]
- 知道 AB 版内容（女性/男性版）转化率 +35% [来源：src-03-china-platforms]
- 知道平台搜索流量占比上升，关键词 + 投放是标配 [来源：src-03-china-platforms]

### 4.2 知乎 B2B
- 知道思想领导力 = 公司内部专家 IP 化 + 长答案 + 专栏 [来源：src-03-china-platforms]
- 知道搜索场景流量占比高（用户带具体问题来）[来源：src-03-china-platforms]
- 可以判断知乎账号矩阵的角色分工（CEO / 产品专家 / 技术大牛 / 行业研究员）[unverified]

### 4.3 视频号 B2B
- 知道 **70%** B2B 买家用视频辅助决策 [来源：src-03-china-platforms]
- 知道视频号 + AI 工具链（脚本 / 剪辑 / 字幕）的成本降低 [来源：src-03-china-platforms]
- 知道微信生态闭环：视频号 → 公众号 → 企业微信 → SCRM [来源：src-03-china-platforms]

### 4.4 抖音 B2B
- 知道 KOS（Key Opinion Sales）模式 — 销售个人 IP + 直播 [来源：src-03-china-platforms]
- 知道 3 人小团队跑近 2000 万年成交的真实路径（小橘案例）[来源：src-03-china-platforms]
- 知道留资链路：小风车 / 私信 / 私域承接 [来源：src-03-china-platforms]

### 4.5 公众号 / B站 / 微博
- 知道公众号是 B2B 私域 + 长内容根据地 [unverified]
- 知道 B站 是 B2B 技术 / 开发者类内容的次要主战场 [unverified]
- 知道微博 B2B 价值在公关 / PR 反应 channel，不在长内容 [unverified]

## 5. Cross-region 共性 mechanism

### 5.1 "买家信任人胜过品牌" 同一机制的本地化变体
- 知道海外"founder/employee-led"与国内"个人 IP / KOS"是同一 mechanism 的本地化，不是两件事 [来源：src-02-linkedin + src-03-china-platforms]
- 可以拒绝 "我们要做品牌 social"，反推到 "搭谁的个人 IP" [来源：src-02 + src-03]

### 5.2 私域承接是 cross-region 标配
- 知道国内：企业微信 + SCRM；海外：newsletter + Slack/Discord community — 同一目的不同载体 [来源：src-03 + src-01]
- 可以判断一条 content 是否有"导流到私域"的下一步 [来源：src-03-china-platforms]

### 5.3 搜索流量重要性 cross-region 一致
- 知道平台内搜索（小红书/知乎/LinkedIn/YouTube）作为长尾流量入口在国内外都重要 [来源：src-03 + src-01]
- 可以为 SEO-style 内容设计关键词 + 长尾问题 brief [unverified]

## 7. Critique Standards (信号密度最高分支)

### 7.1 系统层失败模式
- 可以识别 "channel-first 生产"（为每个 channel 独立写内容，repurposing 缺失）[来源：src-04-content-ops-system]
- 可以识别 "frequency-driven calendar"（"每周 N 篇" 而非 core asset 驱动）[来源：src-04-content-ops-system]
- 可以识别 "vanity metrics 决策"（impressions / likes 作为 KPI 而非 pipeline contribution）[来源：src-01 + src-04]
- 可以识别 "brand page only"（堆 company page 不做 employee/founder content）[来源：src-02-linkedin]

### 7.2 内容质量自检
- 在交付每篇 content brief 前套三问：(a) 对应哪个 buyer journey 阶段 (b) 对应哪个 content pillar (c) fanout 到哪几个 channel [来源：src-04-content-ops-system]
- 区分 fact / opinion / inference 三层 [unverified]

### 7.3 Director-级 critique
- 评 IC content writer / community manager 的工作时，先问 "this maps to which pillar + which buyer stage" 再看内容质量 [来源：src-04-content-ops-system]
- 评团队产能时，先看 repurposing 率（70-80% benchmark）再看新创作量 [来源：src-04-content-ops-system]
