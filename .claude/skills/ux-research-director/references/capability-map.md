## 1. Method Selection & Study Design

### 1.1 方法选型的事实骨架
- 可以在被问任何研究问题时先判定 behavioral vs attitudinal、qual vs quant、natural vs scripted 三轴位置，再挑方法 [来源：src-02-rohrer]
- 知道 20 种主流方法各自的 "best fit / misuse" 配对（usability test / contextual inquiry / diary study / card sort / tree test / A/B / clickstream / survey / interview / participatory design / etc）[来源：src-02-rohrer]
- 可以拒绝"先想方法再想问题"的研究 brief — 强制 stakeholder 先把要回答的决策说清楚 [来源：src-01-hall + src-02-rohrer]

### 1.2 stage-aware 方法判断
- 可以根据产品阶段（0→1 generative / PMF evaluative / scale optimization / maintenance）切换主导方法组 [来源：src-02-rohrer]
- 知道 generative 阶段不该跑 A/B（A/B 只能 evaluate 已有候选）[来源：src-02-rohrer]
- 可以识别 "用 evaluative 方法答 generative 问题" 的错配 [来源：src-02-rohrer]

### 1.3 取样与有效性判断
- 可以判断给定研究问题所需的最小样本量逻辑（5-8 for usability、N=30+ for quant survey 假设检验、purposive vs probability sampling 区分）[unverified]
- 可以识别 sampling bias（self-selection / convenience / survivorship）[unverified]
- 可以拒绝 "we already interviewed 3 customers" 当作 representative 的 claim [来源：src-01-hall]

## 2. Research Execution Craft

### 2.1 访谈与定性深度
- 可以拒绝 "ask users what they want" 型问题，改写为 behavioral / past-experience 型 [来源：src-01-hall]
- 知道 leading question / loaded question / hypothetical question 的识别与重写规则 [来源：src-01-hall]
- 可以在访谈中识别 "user 在表演" 信号并切换问法 [unverified]

### 2.2 Survey 的高阶判断
- 默认对 survey 持怀疑态度 — survey 是 "deceptively easy" 高阶技术，不是入门工具 [来源：src-01-hall]
- 可以识别测量 "satisfaction / preference / intent" 这类心理结构时 survey 的常见 construct validity 失败 [来源：src-01-hall]
- 知道 survey 应答率 / response bias / question order effect 的常见陷阱 [unverified]

### 2.3 Usability test 的边界
- 知道 scripted usability test 测不出 desirability、长期 retention、自然场景下的偏好 [来源：src-02-rohrer]
- 可以识别 "5 users 就够" 的常见误用（只对 evaluative usability、不对 generative discovery）[unverified]

## 3. Critique Standards (信号密度最高分支)

### 3.1 研究失败模式的命名
- 可以识别 "research theater" — 在人造场景做 focus group 等表演型研究 [来源：src-01-hall]
- 可以识别 "validate the design" 措辞陷阱 — 研究目的应是证伪而非证实 [来源：src-01-hall]
- 可以识别 stated preference vs revealed behavior 的混淆 [来源：src-01-hall + src-02-rohrer]
- 可以识别 "research 做完没影响决策" 是系统性失败而非个例 [来源：src-04-uxr-dir-signals]

### 3.2 Insight 质量自检
- 在交付 insight 前，套 "this could be wrong because ___" / "我们假设 ___ 但没验证" / "decision this enables: ___" 三问 [来源：src-01-hall]
- 区分 fact / interpretation / inference 三层，每条 insight 标注属于哪层 [来源：src-01-hall 立场延伸]
- 给出 confidence level 而非绝对断言 [unverified]

### 3.3 Director-级 critique
- 评 IC researcher 的研究 plan 时，先问 "what decision does this enable" 再看方法 [来源：src-04-uxr-dir-signals]
- 评团队多次研究都没改变决策时，把问题诊断到 ops / advocacy / stakeholder 层而非 method 层 [来源：src-03-reops + src-04-uxr-dir-signals]

## 4. Research Operations (ReOps)

### 4.1 8 Pillars 的运营骨架
- 知道 ReOps 8 pillars (Participants / Governance / Tools / Knowledge mgmt / Competency / Admin / Advocacy / Org context) 各自的负责范围 [来源：src-03-reops]
- 可以在被问"我们 research 不 scale" 时定位到具体 pillar [来源：src-03-reops]

### 4.2 Knowledge management / Repository
- 知道 repository 比单次 insight 更高优先级 — 重复研究是 ops 失败信号 [来源：src-03-reops]
- 可以设计 repository 的 taxonomy / tagging / findability 标准 [unverified]

### 4.3 Democratization 与 governance 平衡
- 可以定义哪些研究任务可以 democratize（unmoderated usability、internal survey…）哪些必须 trained researcher 来做（generative discovery、敏感人群访谈、stakeholder 强势型项目）[来源：src-03-reops]
- 可以为非研究员设计 guardrail（recruit 标准、consent、ethics 检查项）[来源：src-03-reops]

### 4.4 Participants & ethics
- 知道 participant recruitment 的 incentive / panel diversity / fatigue 风险 [来源：src-03-reops]
- 可以识别 IRB-style ethics 议题在企业语境下的简化版（consent、harm avoidance、敏感人群）[来源：src-03-reops]

## 5. Insight → Decision (Influence & Advocacy)

### 5.1 把研究翻译成决策语言
- 可以把 research finding 翻成 exec / PM / Eng 各自能消费的形态（PM 要 roadmap input / Eng 要 spec 约束 / Exec 要 strategic implication）[来源：src-04-uxr-dir-signals]
- 不依赖 "deliver report and move on" — 主动追踪 finding 是否被采纳 [来源：src-04-uxr-dir-signals]

### 5.2 拒绝研究请求的判断
- 可以拒绝低 ROI / 答案已知 / 用错方法的 study request 并给替代路径 [来源：src-04-uxr-dir-signals]
- 知道"答应所有 request 是 director 的失败信号" [来源：src-04-uxr-dir-signals]

### 5.3 Insight 流通的失败诊断
- 可以诊断 "insight 没用上" 的原因栈：timing / stakeholder / format / authority / political [来源：src-04-uxr-dir-signals]

## 6. Stakeholder & Business Alignment

### 6.1 与 product / design / eng 协作
- 可以在 product strategy 阶段贡献研究 input，而非只在 build 阶段 [来源：src-04-uxr-dir-signals]
- 知道 PM / Designer / Engineer / DS 各自如何"用研究"以及他们的 failure mode [unverified]

### 6.2 Business alignment
- 可以把 research portfolio 与 OKR / business strategy 显式对齐，删掉孤儿研究 [来源：src-04-uxr-dir-signals]
- 可以为研究 ROI 提供叙事（不是 "几个用户访谈" 而是 "避免了 X 决策风险 / 找到了 Y 机会"）[来源：src-04-uxr-dir-signals]

### 6.3 Exec 沟通
- 可以与 C-级用 5 分钟把一个研究项目压缩讲清楚 [unverified]

## 7. People & Practice Leadership

### 7.1 Hiring & leveling
- 知道 IC researcher vs Director 的 leveling rubric 差异（study craft vs system building）[来源：src-04-uxr-dir-signals]
- 可以为 senior researcher 招聘设计 portfolio review + 模拟评审环节 [unverified]

### 7.2 Mentoring & growth
- 可以把 junior researcher 发展为 independent contributor 的路径设计（structured shadowing、solo project handoff、critique loop）[来源：src-04-uxr-dir-signals]
- 知道 "researcher burnout" 的信号（recruitment fatigue、advocacy fatigue、insight ignored fatigue）[来源：src-03-reops]

### 7.3 Practice building from scratch
- 可以为 "没有 research 实践" 的组织从 0 设计第一年的 practice plan（人 / 工具 / 流程 / governance / repository）[来源：src-04-uxr-dir-signals]

## 8. Ethics, Governance & Failure Modes

### 8.1 研究伦理
- 知道 informed consent、participant compensation、敏感人群（minors、健康相关、脆弱群体）的额外保护 [来源：src-03-reops]
- 可以识别 dark pattern research（fake interviews to confirm preset roadmap）[来源：src-01-hall]

### 8.2 数据治理
- 知道 PII handling、retention policy、cross-border data 限制 [unverified]

### 8.3 Director-级常见失败模式
- "Process theater" — 流程很全但没产出 actionable insight [来源：src-01-hall + src-03-reops]
- "Insight 仓库化" — 把 finding 存进 repository 当成 done，没有 advocate 它进入决策 [来源：src-03-reops]
- 答应每个 stakeholder request 导致 portfolio 散沙 [来源：src-04-uxr-dir-signals]
